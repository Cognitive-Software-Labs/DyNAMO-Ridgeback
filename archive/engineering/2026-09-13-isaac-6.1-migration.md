# Isaac 6.1 migration evidence — 2026-09-13

Recorded dates: 2026-09-13

Tested revisions: unknown

Provenance: partial

This is dated evidence. Missing revisions or preserved worktree inputs limit
reproducibility; no new measurements were made during archive curation.

The September 13 migration was promoted after bounded compatibility controls,
before a statistical exploration baseline. These observations certify neither
later geometry nor present-day coverage or SLAM quality.

## Compatibility controls

Both versions booted headless on the RTX PRO 6000, registered the required ROS
OmniGraph nodes, received 150 monotonic `/clock` messages through system
CycloneDDS, and advanced 40 fixed steps by exactly 1.0000 seconds.

| Camera-disabled warehouse control | 6.0.1.0, driver 580.173.02 | 6.1.0.0, driver 595.84-open |
|---|---|---|
| Coverage | 44.1% | 44.4% |
| Map accuracy | 96.7% | 96.5% |
| RTF | 0.803 | 0.868 |
| Successful goals / aborts | 5 / 0 | 17 / 0 |

These single runs exercised topics, QoS, TF, SLAM, Nav2, scan assembly and
control. They do not establish a statistical comparison; subsequent geometry
changes also prevent treating them as present-day baselines. Raw evidence lives
under `artifacts/isaac-migration-6.1/{pre-driver,post-driver}/`.

## Accepted Isaac 5.1 regression

The representative G1 grasp-lift workload passed on 580.173.02: the custom
scene and checkpoint loaded, policy inference and CUDA PhysX ran, and it
produced 120 frames of 1280×720 H.264 before exiting zero.

After installing signed Ubuntu 595.84-open on kernel 7.0.0-31 and rebooting,
NVIDIA/Vulkan enumeration, Secure Boot signing and the compatibility checker
passed. The same 5.1 workload crashed twice in `librtx.scenedb.plugin.so`
during RTX initialization, before the custom scene or checkpoint loaded.
Repeating the failure argued against a one-time shader-cache issue; the generic
IOMMU warning did not establish its cause.

On 2026-09-13 the operator explicitly accepted loss of that local 5.1 workflow
and chose to proceed with 6.1. This superseded the planned automatic rollback;
it was not a passed 5.1 gate. Driver changes affect every host user. The exact
580 package bundle and both Python environments were retained for recovery.

## Native depth decision

At a controlled 3 m plane, RTX `distance_to_image_plane` returned 100% valid
pixels with a 3.000 m median; `SingleViewDepthCameraSensor` returned finite
all-zero output after 90 updates. NVIDIA's authored D455 asset reproduced the
split. This selected geometric depth plus the D455 disparity model instead of
native stereo depth. Live checks passed both camera resolutions and both
fidelity modes with matching image/cloud stamps and colour optical frames;
a pure occlusion check verified nearest-surface selection. The observation selected the modeled-depth route for that migration.

## MCP evidence limitation

The migration retained the working port-9904 service (MCP 1.25.0, five tools).
The full-LFS audit of NVIDIA `kit-usd-agents` commit
`9e9d69561f81fa368343382a53535f78f8c769fc` found only the 6.0 documentation
corpus and a default `MCP_ISAACSIM_VERSION=6.0`. Rebuilding that revision could
not produce 6.1 answers. This is a dated audit, not a claim about at the recorded date's
upstream; confirm corpus provenance before using MCP answers as version evidence.
