## Observed path

Every hop carries `geometry_msgs/msg/TwistStamped`, and every Nav2 server has
`enable_stamped_cmd_vel: true`. Reliable publishers feed reliable or best-effort
subscribers, which deliver. The auditor flagged no known QoS incompatibility.

| Hop | Publisher → subscriber | Notes |
|---|---|---|
| `cmd_vel_nav` | `controller_server`, `behavior_server` → `velocity_smoother` | smoother limit 1.3 m/s, `velocity_timeout` 1.0 s |
| `cmd_vel_smoothed` | `velocity_smoother` → `collision_monitor` | monitor watches both LiDAR scans, source timeout 1.0 s |
| `cmd_vel` | `collision_monitor` → `twist_mux` | mux input `external`, priority 1, timeout 0.5 s |
| `platform/cmd_vel` | `twist_mux` → `commissioning_speed_guard`, `lighting_node` | mux `use_stamped: true` |
| `platform/cmd_vel_limited` | guard → `platform_velocity_controller` | `reference_timeout` 0.1 s; guard parameters not listable |

The mux's other inputs, all with 0.5 s timeouts, are joystick (priority 10), RC
(12) and interactive marker (8). Its e-stop lock (255) still names
`platform/emergency_stop` in its parameters. The graph shows it subscribed only
to the guard's reliable `platform/emergency_stop_mux`, so the 2026-10-09 remap
was in force. `platform/safety_stop` (254) has no publisher.

The generated controller's `use_stamped_vel: false` (the backlog's open
contract question) did not appear among its readable parameters. The live
controller subscribes to `TwistStamped`, which matches the chain above.

## Finding: the controller's odometry topic has no publisher

`controller_server` subscribes `/r100_0160/odom`. Nothing publishes it. The
platform publishes `platform/odom`, and the EKF republishes it as
`platform/odom/filtered`, which `bt_navigator` and `velocity_smoother` read.
`nav2_params.yaml` sets no `odom_topic` for `controller_server`, so Nav2's
default `odom` applies. The controller therefore receives no current-velocity
feedback. The Isaac adapter also publishes only `platform/odom`, so simulation
probably has the same gap; that was not checked on a live simulator graph. This
does not affect the stop path. It was not changed here, because setting the
topic would change the controller's inputs in every benchmark.
