# Ground-Truth Occupancy Maps

Hand-authored ground-truth maps for the worlds used in exploration sweeps.
Each map defines the "true reachable area" used as the coverage reference.

All files live in `config/ground_truth_maps/` at the repo root.

---

## Maps

| World | Resolution | Origin |
|-------|------------|--------|
| mock_hospital | 0.05 m/px | [-6.338, -9.283, 0] |
| warehouse | 0.05 m/px | [-15.833, -25.528, 0] |
| office | 0.05 m/px | [-13.785, -10.543, 0] |

All maps use the standard ROS occupancy grid format:
- `occupied_thresh: 0.65`
- `free_thresh: 0.196`
- `negate: 0`
- `mode: trinary`

## Part 1 — Generating ground-truth maps (manual teleop)

All three maps were generated by manually teleoprating the Ridgeback through
every reachable area with SLAM running, then saving the resulting occupancy grid.

### Terminal 1 — launch simulation + SLAM

```bash
source ~/Documents/DyNAMO/DyNAMO-Ridgeback/install/setup.bash
ros2 launch ridgeback_autonomy manual_mapping.launch.py world:=<world>
```

Supported worlds: `mock_hospital`, `warehouse`, `office`

This brings up Gazebo, SLAM (slam_toolbox), RViz, twist_mux, and automatically
activates the `platform_velocity_controller` after 15 seconds (it starts
inactive by default in simulation).

### Terminal 2 — keyboard teleop

```bash
source ~/Documents/DyNAMO/DyNAMO-Ridgeback/install/setup.bash
ros2 run teleop_twist_keyboard teleop_twist_keyboard \
  --ros-args --remap cmd_vel:=/r100_0001/cmd_vel -p stamped:=true
```

Controls: `i` forward · `,` backward · `j` rotate left · `l` rotate right · `k` stop · `q`/`z` speed up/down

Drive through every room, corridor and doorway — at least two passes.

### Terminal 3 — save the map when done

```bash
ros2 run nav2_map_server map_saver_cli \
  -f ~/Documents/DyNAMO/DyNAMO-Ridgeback/config/ground_truth_maps/<world> \
  --ros-args --remap map:=/r100_0001/map -p map_subscribe_transient_local:=true
```

Replace `<world>` with `mock_hospital`, `warehouse`, or `office`.

## Part 2 — Autonomous exploration

### Launch exploration

```bash
source ~/Documents/DyNAMO/DyNAMO-Ridgeback/install/setup.bash
ros2 launch ridgeback_autonomy ridgeback_exploration.launch.py \
  world:=hospital explorer:=custom
```

Valid world names here: `hospital`, `office`, `warehouse` (not `mock_hospital`).

This launches Gazebo + full Nav2 stack + the custom frontier explorer.
The robot will autonomously explore, plan paths, and handle recovery if stuck.

### Expected behaviour

- **Frozen then moving**: Nav2 recovery is working as designed — it clears the
  local costmap and replans when stuck near obstacles.
- **Moving slowly**: Gazebo real-time factor (RTF) may be below 1.0 due to
  CPU load from running Gazebo + SLAM + Nav2 + RViz simultaneously.
- **Clipping walls**: SLAM latency at low RTF means the costmap sees walls
  slightly after the robot reaches them. Not a config problem — expected on
  a single machine.

## Part 3 — Live coverage monitoring

Run this in a separate terminal **while exploration is running**. It subscribes
to the live SLAM map, and when you press `Ctrl+C` it computes a final
cell-by-cell comparison against the ground-truth and saves the result to a file.

```bash
source ~/Documents/DyNAMO/DyNAMO-Ridgeback/install/setup.bash
python3 ~/Documents/DyNAMO/DyNAMO-Ridgeback/config/ground_truth_maps/live_coverage_monitor.py \
  ~/Documents/DyNAMO/DyNAMO-Ridgeback/config/ground_truth_maps/mock_hospital.pgm
```

Press `Ctrl+C` when exploration is done. Results are saved to:
- `mock_hospital_coverage_result.txt` — full stats
- `mock_hospital_coverage_result.png` — visualization

### How the comparison works

Both grids are normalised to `{-1=unknown, 0=free, 1=occupied}` and spatially
aligned using their `.yaml` coordinate metadata. Each cell is subtracted:

| slam \ gt | free (0) | occupied (1) |
|-----------|----------|--------------|
| free (0)  | diff = 0 ✓ | diff = -1 |
| occupied (1) | diff = +1 | diff = 0 ✓ |
| unknown (-1) | counted as unexplored | — |

**Coverage %** = cells where `slam=free` AND `gt=free` / total `gt=free` cells

### Options

| Flag | Default | Description |
|------|---------|-------------|
| `--topic` | `/r100_0001/map` | SLAM occupancy grid topic |
| `--output` | `<gt>_coverage_result.txt` | Custom result file path |
| `--save-image` | `<gt>_coverage_result.png` | Custom visualization path |

## Part 4 — Screenshot comparison (no simulation needed)

Compare any screenshot or exported image of an explored map against a
ground-truth PGM without running ROS. Useful for quick checks.

```bash
python3 ~/Documents/DyNAMO/DyNAMO-Ridgeback/config/ground_truth_maps/compare_image.py \
  ~/Downloads/hospital_explored.jpeg \
  ~/Documents/DyNAMO/DyNAMO-Ridgeback/config/ground_truth_maps/mock_hospital.pgm \
  --crop 30 0 0 0
```

`--crop 30 0 0 0` trims the top 30 px (HUD / UI overlay) before processing.

Results saved to:
- `mock_hospital_image_compare.txt`
- `mock_hospital_image_compare.png`

**Note:** Screenshot comparison is less accurate than `live_coverage_monitor.py`
because it requires pixel thresholding and image registration (ORB feature
matching) to align the screenshot with the PGM. Use it for rough checks only.

## Known quirks

- **`platform_velocity_controller` starts inactive in simulation.** The
  `manual_mapping.launch.py` activates it automatically after 15 s. If the
  robot does not respond, check and activate manually:
  ```bash
  ros2 service call /r100_0001/controller_manager/list_controllers \
    controller_manager_msgs/srv/ListControllers {}

  ros2 service call /r100_0001/controller_manager/switch_controller \
    controller_manager_msgs/srv/SwitchController \
    "{activate_controllers: ['platform_velocity_controller'], \
      deactivate_controllers: [], strictness: 2}"
  ```

- **`twist_mux` requires `TwistStamped`** (`use_stamped: True` in
  `~/clearpath/platform/config/twist_mux.yaml`), so teleop must include
  `-p stamped:=true`.

- **`map_saver_cli` QoS mismatch** — slam_toolbox publishes with
  `transient_local` QoS. Always add `-p map_subscribe_transient_local:=true`
  or the saver will time out.

- **World name difference** — `manual_mapping.launch.py` accepts `mock_hospital`
  but `ridgeback_exploration.launch.py` requires `hospital`.
